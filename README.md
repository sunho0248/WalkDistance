# 보행거리 계산 프로그램

건축 DXF 도면의 벽을 격자로 변환하고, 여러 출구 중 가장 가까운 곳까지의 최단
보행거리를 표시하는 C# .NET 8 WPF 데스크톱 프로그램이다. 경로 탐색과 UI는
Simulex 등 상용 제품의 코드·UI·자산을 참조하거나 복제하지 않고 독자 구현했다.

## 요구 환경과 실행

- Windows 10/11 x64
- .NET 8 SDK

```powershell
dotnet restore WalkDistance.sln
dotnet run --project src/WalkDistance.App/WalkDistance.App.csproj
```

## 사용법

1. `파일 > DXF 열기`에서 도면을 연다. `$INSUNITS`가 없거나 unitless이면 표시되는
   창에서 원본 좌표 단위(mm, cm, m, inch, ft)를 반드시 선택한다.
2. `출구 지정 모드`를 켠 뒤 시작점과 끝점을 차례로 클릭해 출구 선분을 지정한다.
   화면 기준 약 10~12픽셀 이내에 벽/도형 선분이 있으면 클릭 지점과 마우스를 따라
   움직이는 미리보기 끝점이 모두 그 선분 위로 자동 스냅되어, 확대/축소 배율과
   무관하게 문 끝점이 도면 geometry에 정확히 붙는다. 근처에 스냅할 선분이 없으면
   기존처럼 클릭한 위치에 자유롭게 배치되며 클릭이 막히지 않는다. 첫 점을 찍은
   뒤에는 마우스를 따라 미리보기 선이 표시되고, 끝점을 클릭하면 즉시 선분이
   확정된다. 이때 우클릭하면 지정 중인 선만 취소한다. 지정 중인 선이 없을 때
   우클릭은 완료된 출구를 절대 삭제하지 않으며, 선택된 출구가 있으면 선택만
   해제하고 없으면 아무 동작도 하지 않는다(항상 예측 가능한 동작). 출구 지정
   모드를 끄면 지정 중인 선이 취소된다.
3. 출구 지정 모드를 끈 상태에서 완료된 출구 선분 근처를 클릭하면 그 출구가
   파란색으로 강조 표시되어 선택되고 상태 표시줄에 안내가 뜬다. 이 상태에서
   `Delete` 키를 누르면 선택된 출구만 삭제되고 출구 개수와 분석 상태가 갱신된다.
   삭제는 도면(캔버스)에 포커스가 있을 때 동작하며, 셀 크기 입력 칸을 편집 중일
   때는 `Delete` 키가 텍스트 편집에만 사용되고 출구를 삭제하지 않는다. 출구가 없는
   빈 곳을 클릭하거나 우클릭하면 선택이 해제된다.
4. 미터 단위 셀 크기를 입력하고 `보행거리 계산`을 누른다. 5 m 간격 등거리선이
   히트맵 위에 표시되며, 5 m 전용 선(5, 15, 25...)은 얇고 옅은 회색, 10 m 배수 선은
   굵고 검은색으로 강조된다. 겹침을 줄인 숫자 라벨은 정확히 10 m 배수에만 표시되며,
   같은 거리라도 서로 떨어진 등거리선 구성요소마다 하나씩 표시된다. 선택 기준거리는 비워 두면
   꺼지고, 0 이상의 유한한 숫자를 입력하면 그 거리보다 큰 셀(`거리 > 기준거리`)을
   보라색으로 강조하고 기준 등거리선을 흰색으로 표시한다. 기준거리는 현재 실행에만
   적용되며 프로젝트 JSON에는 저장되지 않는다. 입력값은 즉시 검증되고 Enter를 누르거나
   포커스를 옮기면 기존 계산 지도에 반영되어 다시 계산할 필요가 없다. 잘못된 값은 입력
   테두리와 도움말로 표시되고, 고치는 동안 직전의 유효한 기준과 계산/조회 결과는 그대로
   유지된다.
5. 계산 뒤 도면의 임의 지점을 클릭하면 가장 가까운 출구까지의 보행거리와 실제
   좌표에서 시작하는 안전한 경로가 표시된다. 최장 경로와 조회 경로의 중간에는 각각
   경로 색상의 거리 라벨이 소수점 둘째 자리까지 표시된다. 다른 지점을 클릭하면 기존
   조회 점선과 거리 라벨은 새 경로로 교체된다.
   건물 외부, 벽, 도달 불가능한 지점을 구분해 안내한다. 벽 외곽선이 열려 있으면
   이전 결과와 경로를 지우고 계산을 거부하므로, 먼저 선을 연결해 닫힌 공간을 만든다.
   `디스턴스 맵`과 `보행경로` 체크 상자는 기본으로 켜져 있으며 서로 독립적이다. 디스턴스 맵은
   히트맵·등거리선·라벨·기준거리 표시만, 경로는 최장/조회 점선과 거리 라벨만 숨긴다. 전환해도
   계산 결과, 조회점, 벽, 출구, 마커와 상태 문구는 유지된다.
6. `프로젝트 저장`은 벽 geometry, 출구 선분, 셀 크기, 단위 배율을 v3 JSON 안에
   넣는다. 원본 DXF를 옮기거나 삭제해도 v3 프로젝트를 다시 열 수 있다.

기존 v1 경로 기반 프로젝트와 v2 자체 포함 프로젝트의 포인트 출구는 같은 위치의
길이 0인 선분으로 자동 변환된다. v1은 원본 DXF가 남아 있어야 하며, DXF에 단위가
없으면 새 DXF와 마찬가지로 사용자에게 단위를 묻는다.

## 지원 DXF와 단위

- ASCII DXF의 `LINE`, `LWPOLYLINE`, `POLYLINE`/`VERTEX`, `CIRCLE`, `ARC`
- `$INSUNITS` 1~24를 미터로 변환(0 또는 누락은 사용자 선택)
- ENTITIES 섹션이 잘못되었거나 지원되는 벽이 하나도 없으면 오류 처리
- 원과 호는 격자화를 위해 선분으로 분할

[`samples/sample-room.dxf`](samples/sample-room.dxf)는 미터 단위의 12 m × 8 m 방과
상부 통로가 있는 내부 벽을 담은 반복 검증용 도면이다.

## 알고리즘

벽 선분을 입력 셀 크기의 격자로 rasterize한 뒤, 격자 테두리에서 4방향 반복
flood-fill해 테두리와 연결된 자유 셀을 외부로 분류한다. 벽도 외부도 아닌 닫힌 내부
셀만 보행 가능하며 출구 source, 거리장, 조회, 최대값, 경로와 히트맵이 모두 같은
판정을 사용한다. 그 뒤 .NET 우선순위 큐 기반 Theta*를
수행한다. 한 출구 선분에서 만든 접점들은 하나의 논리 출구 그룹으로 묶고, 출구 그룹별
다중 소스 field를 순차 계산한 뒤 각 셀에서 최소 거리와 winning group을 합친다. 따라서
서로 다른 출구의 탐색 label이 합쳐져 더 짧은 출구 경로를 잃지 않는다. 8방향 이웃을
확장할 때 현재 predecessor에서 다음 셀까지 보수적인 supercover line-of-sight가 있으면
그 직선 길이로 완화한다. 셀별 거리, 최대 거리, 히트맵, 등거리선과 표시 polyline은 같은 any-angle
기하 길이를 사용하며 별도의 사후 string-pull은 하지 않는다. 대각선 양옆 중 한 셀이라도
벽이면 기본 이동을 금지해 코너 컷을 막는다.

10 m 배수 등거리선 라벨은 셀 크기에서 정한 작은 좌표 허용 오차 안에서 끝점이 맞닿는
선분들을 공간 해시와 union-find로 조립한 연결 구성요소마다 하나씩 배치한다. 전체 선분 쌍을
비교하지 않으며 입력 순서를 유지하고, 거리 레벨이나 일반/기준 등거리선 종류가 다르면 합치지 않는다.

각 출구 인접 셀에는 실제 출구 선분상의 접점을 저장한다. 일반 line-of-sight는 모든 벽
셀을 거부한다. 지정된 출구 접점에서 끝나는 마지막 raster 셀은 원본 벽 선분을 다시
검사해, 그 셀의 벽이 출구와 맞닿거나 겹치고 실제 경로와 벽의 교차점/겹침이 출구 선분
안에 있을 때만 예외로 허용한다. 따라서 벽 위 출구의 양쪽은 연결하면서 실제 경로와
교차하는 별도 벽은 통과하지 않는다. 실제 조회 좌표에서는 모든 논리 출구 field의 안전한
predecessor 경로를 평가해 최단 경로를 고르고, 정확한 셀 중심 조회만 winning field를 쓴다.
UI는 한 번 반환된 polyline과 그 길이를 함께 쓴다.

출구에서 도달할 수 없는 내부 셀은 무한대로 유지하며 최대값과 가장 먼 지점 선정에서
제외한다. UI는 제외된 셀 수를 알린다. `N`을 셀 수, `D`를 셀 단위 격자 대각 길이,
`G`를 출구 수, `S`를 출구 인접 source 수라고 하면 persistent 메모리는 `O(N+S)`이고,
외부 분류는 반복 방식 `O(N)` 시간·메모리이며 재귀를 사용하지 않는다. 전체 계산의 최악 시간은 출구 수에 비례하는 `O(G·(N·D + N log N))`이다. 실제 좌표 조회도
`G`개 출구 group field를 평가하므로 `O(G·(N·D + N log N) + L)`이며, 정확한 셀 중심은
winning field 하나만 재계산한다. quadratic string-pull은 없다.
4,000,000셀은 할당 폭주를 막는 상한일 뿐 속도나 메모리 성공을 보장하지 않으므로 큰
도면에서는 셀 크기를 키워야 한다.

## 검증

```powershell
dotnet test WalkDistance.sln
dotnet restore src/WalkDistance.App/WalkDistance.App.csproj -r win-x64
dotnet build src/WalkDistance.App/WalkDistance.App.csproj -c Release -r win-x64 --no-restore
dotnet publish src/WalkDistance.App/WalkDistance.App.csproj -c Release -r win-x64 --self-contained true --no-restore -o dist/win-x64
```

반복 가능한 수동 스모크 절차:

1. 샘플 DXF를 열고 출구 지정 모드에서 벽 근처(화면 기준 약 10~12픽셀 이내)를
   두 번 클릭해 출구 선분을 만든다. 클릭한 지점과 그 사이 마우스를 따라 움직이는
   미리보기 끝점이 모두 실제 벽/도형 선분 위로 자동 스냅되어 문 끝점이 geometry에
   정확히 붙는지 확인하고, 상태 표시줄에 자동 스냅 안내 문구가 뜨는지 확인한다.
   벽에서 멀리 떨어진 곳을 클릭하면 스냅되지 않고 클릭한 위치 그대로 자유롭게
   배치되는지도 확인한다.
2. 새 선분의 첫 점만 찍고 우클릭해 pending 선만 사라지고 기존 완료 출구는 그대로
   남는지 확인한다. 지정 중인 선이 없을 때 우클릭하면(선택 없음) 출구가 하나도
   삭제되지 않고 "취소할 그리기나 선택이 없습니다" 안내만 뜨는지 확인한다.
3. 출구 지정 모드를 끄고 완료된 출구 선분 근처를 클릭해 파란색으로 강조 선택되는지
   확인한 뒤 `Delete` 키를 눌러 그 출구만 삭제되고 개수가 갱신되는지 확인한다. 이어서
   셀 크기 입력 칸(`0.05`)을 클릭해 포커스를 옮기고 `Delete`를 눌러도 출구가 삭제되지
   않고 텍스트 편집에만 적용되는지 확인한다.
4. 기본 셀 크기 `0.05`로 계산해 히트맵, 5 m 간격 등거리선, 10 m 배수의 굵고 검은 주요선과 숫자 라벨,
   5 m 전용 구간의 얇고 옅은 회색 보조선, 빨간 최장거리 지점과 출구까지의 점선 경로 및
   경로 색상의 소수점 둘째 자리 거리 라벨이 나타나는지 확인한다. 저장된 프로젝트를 다시 열면 새 프로젝트 기본값이 아니라
   그 프로젝트에 저장된 셀 크기가 그대로 입력 칸에 반영되는지 확인한다.
   기준거리에 `10`을 입력해 10 m 초과 영역과 흰 기준선이 표시되는지, `10`인 셀은
   초과 강조되지 않는지 확인한다. 두 표시 체크 상자를 각각 껐다 켜도 조회와 상태가
   유지되고, 프로젝트 저장/열기 뒤 기준거리 입력은 저장값으로 복원되지 않는지 확인한다.
5. 출구 지정 모드가 꺼진 상태에서 도면의 서로 다른 지점을 차례로 클릭해 거리 문구와
   조회 점선이 중복되지 않고 새 경로로 갱신되는지 확인한다.
6. 프로젝트를 저장하고 샘플 DXF를 임시로 다른 곳에 옮긴 뒤 출구 선분까지 그대로
   열리는지 확인한다.
7. 셀 크기를 매우 작게 입력해 4,000,000셀 제한 안내가 나타나는지 확인한다.

자동 테스트는 단위 변환/단위 확인, 모든 지원 엔티티, v3 선분 round-trip, v1/v2
마이그레이션, 출구 편집 상태(클릭-클릭 확정, 우클릭 취소, 완료 출구 선택/삭제,
선택 상태의 초기화/로드/전체 삭제/모드 전환 시 정합성), 선분 source, 실제 좌표
기반 직선/우회 경로, 출구 접점, 격자 상한, unreachable 제외, 벽 충돌과 대각선
코너 컷 방지를 다룬다. 출구 스냅용 최단점/투영 geometry API(`GeometrySnap`)는 내부
투영, 끝점 clamping, 퇴화 선분, 다중 선분 중 최근접 선택, 허용 오차 경계값(정확히
일치/초과), 좌표·허용 오차 유효성 검증을 다룬다. 등거리선 구성요소 테스트는 연결 사슬,
같은 레벨의 분리된 집합, 허용 오차 경계, 레벨/일반·기준 종류 분리와 UI 라벨 연결을 검증한다.

## 제약

- 바이너리 DXF, spline, block insert 확장, hatch 영역은 지원하지 않는다.
- 벽은 선분을 반 셀 간격으로 샘플링해 막힌 셀로 변환하므로 세밀한 도면은 더 작은
  셀 크기가 필요하다.
- Theta*는 raster 격자와 보수적인 line-of-sight에 대한 any-angle 근사이며 원본 벡터
  geometry의 전역 최단경로를 보장하지 않는다. 다만 보고하는 모든 거리와 경로는 같은
  Theta* predecessor metric을 사용한다.
- 본 MVP는 선 중심을 벽으로 취급하며 벽 두께, 문 폭, 사람 반경은 모델링하지 않는다.

- `src/WalkDistance.Core`: DXF, geometry, 격자, Theta*, 프로젝트 파일
- `src/WalkDistance.App`: 한국어 WPF UI와 히트맵 렌더링
- `tests/WalkDistance.Core.Tests`: Core 자동 테스트
- `samples`: 수동 스모크용 DXF
